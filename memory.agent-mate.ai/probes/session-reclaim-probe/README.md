# 3.13 mcp:会话回收判据探针（Sprint 4 `3.4` 的开工前置）

> **研究类探针，不入制品**（[`ADR-017`](../../specs/adr/ADR-017-complexity-probe-before-real-build.md)）。为 Sprint 4 `3.4`「mcp:会话回收」回答「`AC3.4` 的『子进程已退出 + 不残留僵尸进程或占用中的库文件句柄』**怎么判才算判死**」，以及 SDK 的 `pid` 字段在两种拓扑下**到底指向谁**。
>
> 交付对象：本 Sprint `3.4`；判据口径落 [`../../specs/web-portal/web-design.md`](../../specs/web-portal/web-design.md) §12.5 与 [`../../specs/mcp/mcp-design.md`](../../specs/mcp/mcp-design.md) §5.6.2。

## 为什么必须先用探针

`3.4` 是本仓**第一次**要给「回收」写**验收判据**（`session.ts:8-11` 的归属说明），而它要判的三件事在 SDK 与容器两层**都不是想当然**：

1. `AC3.4` 写「不残留**僵尸进程**或**占用中的库文件句柄**」—— 这两条**没有现成观测手法**：「数进程」在容器里能做（`3.12` 已钉死），但「**谁**持有库句柄」与「有没有僵尸」都要另找判据；
2. `web-design.md` §12.5 声明会话记录字段 `child`（子进程句柄 / PID），而 SDK 的 `StdioClientTransport.pid` 在**本机借壳**（`docker exec`）下指向**宿主的 docker 客户端**，不是容器里的上游进程 —— 不实测就会把契约写错（下游判据全跟着错）；
3. SDK **不提供**任何空闲机制（`shared/protocol.js` 只有每请求超时与 ping 自动 pong）⇒ 「空闲超时」必须自己起计时器 —— 这条由静态核实钉死，不需探针。

## 跑法

**自包含**（本目录自带 `node_modules`，不需要门户）：

```bash
cd memory.agent-mate.ai/probes/session-reclaim-probe
npm install
node probe.mjs
```

| 项 | 值 |
|---|---|
| 退出码 | `0` 全部断言通过 · `10` 前置不足（容器未运行 / 取不到 docker endpoint）· `30` 断言失败 |
| 原始输出 | `out/probe-<时间戳>.log`（**不入库**，见 `.gitignore`） |
| 拓扑 | **不经门户**：直接起一个 stdio 会话（`docker exec` 借壳），因为要测的是 **SDK 与容器的观测语义**，与门户无关；`3.4` 的真上游 e2e 会把这套判据挂到门户链路上 |
| 副作用 | 在容器内**预建并删除** `/data/users/probe313`（借 root；不碰其它用户），**真写一次** `memory_store`（走真 embedding） |

## 由结论导出的硬约束（`3.4` 直接照用）

| 要判的事 | 判据实现 |
|---|---|
| 子进程归零 | ① 容器内 `cmdline` **精确前缀**计数回落基线（手法见 `3.12`）② 扫 `/proc/<pid>/fd` 找指向 `/data/users/<handle>/ai-memory.db*` 的符号链接 ⇒ 收尾后必须为空 ③ 扫 `/proc/<pid>/stat` 的 `state=Z`（按 `comm` 认名）⇒ 收尾后必须为空 |
| `child`（PID）字段的语义 | = **门户侧被 spawn 的那个进程**（`transport.pid`，连接后有、`close()` 后无）。**本机借壳下它是宿主的 `docker` 客户端** ⇒ 契约按生产 β′ 写、**判据一律走容器内观测** |
| 空闲超时 / 最长时长 | 自己起计时器（SDK 无内置）；**取值归 `4.1`**（键名已在 `web-design.md` §12.9 登记） |
| 吊销事件回收 | 实现位置**必须遵守 `3.3` 的不可侵扰纪律**：只回收**属于本令牌**的会话 |

## 边界（如实登记）

- **不经门户**：本探针证的是 SDK 与容器的观测语义；「门户链路上这三条判据也成立」由 `3.4` 的真上游 e2e 覆盖。
- **只测单会话**：并发下判据是否互相干扰（多个库句柄同时在册）未测 —— `3.3` 的 e2e 已证两会话两进程互不牵连，`3.4` 若要在并发下判「归零」，需自行扩展。
- **僵尸判据是「无则通过」型**：本机环境**没有**产生过僵尸（Node 会自动回收子进程），故该判据只证「可读且当前为空」，**未证「能检出僵尸」**（没有反向用例）。如实登记。
- 本探针**不改**产品代码（本轮只做开工准备）。
