## §0 测试策略（L0–L3 分层）

| 层 | 名称 | 手段 | 防的失败模式 |
|---|---|---|---|
| **L0** | 组件/单元 | 门户自身逻辑：`handle` 白名单校验、模板占位符替换与断言、令牌哈希与常时比较、审计落库 | 输入校验与密钥处理错误（T2/T3） |
| **L1** | 集成（本地） | 门户容器 + 共享卷 `ai_memory_data`，建用户 → 签发 key → 经 `/mcp` 建会话 → 写入 → 断开 | 会话生命周期、子进程回收、库路径解析（S4） |
| **L2** | 端到端（真实客户端） | Cursor/Claude 以 `Authorization: Bearer memo_…` 指向 `<MCP_HOST>/mcp`，完成 initialize → tools/list → 实调用 | 真实客户端的传输/重连差异、CF 面隔离误配 |
| **L3** | 上线门禁（生产） | 面隔离、吊销即时生效、无 docker socket、UID/GID 对齐、备份边界 | 上线前的**阻断级**条件（含隔离负向验收） |

> **门槛**：L3 全绿才允许对外提供服务；其中 **负向用例（S4 / 路径穿越 / 面隔离）不过 = 阻断**。
>
> **UI 设计系统与版式的落层（`S14`）**：设计令牌、控件尺度这类可对令牌与计算样式下断言的项属 **L0**；原型结构与实现一致性（链路、列宽、固定外框、四语言词表、分页）属 **L2**（浏览器侧端到端）。原型阶段由验收脚本覆盖（`specs/web-portal/mockups/.verify/`，**不入库、不入制品**），实现阶段须复跑同一组断言 —— 逐页映射见 [`web-design.md`](./web-design.md) §14。

### §1.1 覆盖率口径与门禁（`PSP-W1` 起）

**入口**：`make portal-coverage`（= [`scripts/portal-coverage.sh`](../../scripts/portal-coverage.sh)）。两段式判定，退出码可分流（调用方不解析文案）：**0** 通过 · **10** 测试未通过（先修测试，覆盖率数字此时无意义）· **11** 覆盖率未达阈值 · **20** 运行错误 · **30** 前置不满足（未装依赖或 provider）。

| 项 | 值 |
|---|---|
| 统计范围 | `admin_portal/src/**` —— `include` 全量、`exclude` **为空**（不排除任何业务逻辑） |
| 阈值（[`vitest.config.ts`](../../admin_portal/vitest.config.ts) 的 `test.coverage.thresholds`，低于即**失败**） | 语句 **92** · 分支 **85** · 函数 **96** · 行 **93** |
| 实测（2026-09-22，247 项离线测试；上一轮） | 语句 **94.87%** · 分支 **88.25%** · 函数 **98.77%** · 行 **96.39%** |
| 实测（2026-09-23，261 项离线测试） | 语句 **92.78%** · 分支 **85.90%** · 函数 **97.76%** · 行 **94.26%**（四项均达标；语句边距 **+0.78** 偏薄 —— 下降是因为新增了 `dev-login` 与 `admin-api` 的分支，不是覆盖退化） |
| 首测基线（同批补测前，作为对照） | 语句 79.30% · 分支 72.74% · 函数 88.02% · 行 80.05% |
| 产物 | `admin_portal/coverage/`（`index.html` 逐文件明细；已在 `.gitignore` 忽略，不入库） |

**为何不排除业务逻辑**：阈值若靠排除「不好测的模块」凑出来，门禁就失去意义。确**不可在测试进程内执行**的只有两处**进程入口**：`src/server.ts` 的 `main()` 与 `src/web/db/migrate.ts` 的 CLI 引导块（会绑定端口 / 注册信号 / 写 `process` 流并置退出码；其内部各段逻辑另有单测与集成测试覆盖）。对它们采用**源码内** `v8 ignore start|stop` 显式豁免并写明理由 —— 不是配置层一刀切，也不是静默排除。

**保留不测的分支（逐条理由，不计为缺口）**：① `error instanceof Error ? … : String(error)` 的 else 侧（Node 的 `fs` / `jose` 只抛 `Error` 实例，该侧为防御性保留）；② `services/keys.ts` 的 `catch`（需构造「用户目录被文件占位」这类损坏态，其判断本身的单测已在位）；③ i18n `t()` 的 `?? reference[key]` 右支（仅在四语言词表键集合不一致时可达，而那种情况**启动期已 fail-loud 拒绝启动**）。

**门禁有效性的双向验证**：正常阈值通过（`rc=0`）；人为把 `thresholds.lines` 抬到 99 时**失败**（`rc=1`）⇒ 证明它不是「写了但不会挡」的摆设。

**为何不进 pre-commit 钩子**：钩子当前只跑 `secret-check`（秒级）；覆盖率运行属**收口期**成本，塞进钩子会让每次提交都变慢而收益有限 ⇒ 作为独立目标在验收 / 回顾时执行。

> **本机手工验收的最短路径（2026-09-23 实测；三处前提缺任一都会得到 `503 upstream_unavailable`，**不是**桥的缺陷）**：① `.env.local` 补 `PORTAL_LAUNCH_OVERRIDE` 借壳 `docker exec`（本机不能执行镜像内的 linux 二进制；该覆盖**只换 `command`/`args`，env 由覆盖命令自行转发**）；② 设 `PORTAL_MCP_HOST=127.0.0.1` —— 真实客户端**改不了 `Host` 头**，用 `mcp.localhost` 时只有能自定义 Host 的 `curl` 连得上；③ 先 `docker exec -u 0 <容器> sh -c 'mkdir -p /data/users/<handle> && chown aimem:aimem /data/users/<handle>'` —— 上游**不创建库文件的父目录**，且门户建的宿主目录与容器内 `/data/users/<handle>` **不是同一路径**。随后 `make portal-up` → 管理面签发令牌 → 客户端指向 `http://127.0.0.1:<PORT>/mcp` 并带 `Authorization: Bearer memo_…`。**失败面可用 `curl` 直接验**：带 `-H 'Host: mcp.localhost'` 与 `-H 'accept: application/json, text/event-stream'`（缺 `accept` 得 406，属协议层门禁）时，无令牌 / 错前缀 → **401**，管理面 Host → **403**。
> **在线 / 离线边界（如实登记）**：**离线套件不覆盖真 Cloudflare Access 链路** —— 离线用自签 JWT（测试密钥对）验证的是验签与状态机逻辑；`AC10.1` / `AC10.5` 的**端到端**验收需要一个**经隧道暴露、受 Access 应用保护的域名**，在具备隧道与 Service Token 时由 `scripts/portal-e2e.sh --online` 执行。缺前置时该套件**以退出码 40 明确跳过**（2026-09-23 实测：输出 `SKIP: 在线套件跳过 —— 未提供 PORTAL_E2E_ONLINE_BASE_URL`；不伪装通过）。
> **调用入口的退出码差异（2026-09-23 实测，避免误判）**：`make portal-e2e ARGS=--online` 会把非零退出码**折叠为 2** ⇒「40 明确跳过」与「41 失败」在 make 层面**不可区分**；**机器调用方（CI / 脚本）须直接调用 `scripts/portal-e2e.sh`** 才能拿到真实码（脚本头已写明）。
> **本批留下的唯一未测项**：在线套件的**真链路运行**（缺 `PORTAL_E2E_ONLINE_BASE_URL` 与 Access Service Token 两项环境变量，只能由持有者执行）。这是「**未测**」，不是「不通」—— 链路本身已于 2026-09-22 由 `tunnel-dev.sh --verify` 验证（Service Token → HTTP 200、OK ⑤）。
> 离线套件另用 `CF_Authorization` cookie 走浏览器导航分支，与生产路径一致。
