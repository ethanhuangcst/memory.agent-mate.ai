# web-stories — 门户用户故事与验收条件

> **状态**：v1.0（specs 整合版） · as_of 2026-09-20
> **真相源**：需求与设计见 [`web-design.md`](./web-design.md)；测试见 [`web-test.md`](./web-test.md)；隔离机制见 [`../mcp/mcp-design.md`](../mcp/mcp-design.md) §0/§6
> **角色**：**管理员**（邀请制，经 Cloudflare Access 进入管理面）· **用户**（持 `memo_` 令牌的 MCP 客户端使用者）· **主人**（SSH 保底路径）
> **边界**：只写「谁要什么、怎样算完成」；实现与部署分别见设计文档与 [`../deployment.md`](../deployment.md) §12.2

## S1 创建用户（邀请制）

> 作为**管理员**，我希望在管理面创建一个用户（handle），以便为其分配独立的记忆空间。
> 不开放自助注册。

| AC | Given / When / Then |
|---|---|
| AC1.1 | 管理员在建用户界面提交合法 handle → 创建成功，并**同时创建** `/data/users/<handle>/`（mode `0700`，属主对齐容器内 `aimem`）。**前置**：`/data/users` 为 `root:aimem 2775`（setgid 一次性引导，[`../deployment.md`](../deployment.md) §4.4）⇒ 门户以 `aimem` 身份即可创建，**无需 root**；门户启动自检不可写即拒绝启动 |
| AC1.2 | handle 不匹配 `^[a-z0-9_-]{1,32}$` 或已存在 → 拒绝并给出明确原因 |
| AC1.3 | handle 含 `../`、`/` 等路径穿越字符 → 拒绝（**不得**创建出预期外的目录） |
| AC1.4 | 非管理员（无 CF Access 身份 / 在 MCP 域名请求管理 API）→ 拒绝，且**无法**创建任何用户或 key |
| AC1.5 | 创建动作写入审计（事件 `create_user`） |

## S2 签发 / 轮换 / 吊销 / 删除令牌

> 作为**管理员**，我希望对用户的 `memo_` 令牌做完整生命周期管理，以便泄露时可即时止血且保留审计链。

| AC | 描述 |
|---|---|
| AC2.1 | **签发**：生成 `memo_` + 32 字节 CSPRNG（base64url 无填充，43 字符）；**明文仅在创建响应中出现一次**，之后不可取回 |
| AC2.2 | 库内**只存** `sha256(token)` + `key_prefix`（`memo_` + 前 8 字符）；对比用常时比较 |
| AC2.3 | 签发时**幂等确保**用户目录存在（不创建 DB 文件 —— 由 ai-memory 首次使用时自动创建） |
| AC2.4 | **列出元信息**：前缀 / 标签 / 创建时间 / 最后使用时间；**不含明文** |
| AC2.5 | **轮换** = 吊销旧 + 签发新；旧 key **不可复活** |
| AC2.6 | **删除** = 软吊销（置 `revoked_at`，立即失效但**保留审计链**，不做物理删除） |
| AC2.7 | 吊销后：新建会话被拒；**既有会话被终止**（门户 kill 子进程） |
| AC2.8 | 签发 / 轮换 / 吊销均写入审计 |

## S3 用户通过 MCP 端点接入

> 作为**用户**，我希望用令牌把客户端指向 `https://<MCP_HOST>/mcp`，以便无需 SSH 即可使用记忆能力。

| AC | 描述 |
|---|---|
| AC3.1 | 客户端带 `Authorization: Bearer memo_…` 建立会话成功，可完成 `initialize` → `tools/list` → `tools/call` |
| AC3.2 | 无令牌或令牌已吊销 → 拒绝建立会话（**不**降级为匿名访问） |
| AC3.3 | MCP 面**不被 Cloudflare Access 拦截**（命令行客户端无法完成浏览器 SSO 重定向，被拦会表现为「连不上」） |
| AC3.4 | 会话结束后该用户的 ai-memory 子进程**已退出**（无僵尸、无泄漏） |
| AC3.5 | 同一用户的多把 key → 解析到**同一个 handle / 同一个库**（多设备共享同一份记忆） |

## S4 跨用户隔离

> 作为**用户**，我希望我的记忆只有我能看到，以便不与他人串号。

| AC | 描述 |
|---|---|
| AC4.1 | 用户 A 写入后，用户 B 检索**命中不到**（且不报错） |
| AC4.2 | 用户 B `memory_get <A 的记忆 id>` → **不可见**（`memory not found`） |
| AC4.3 | 每次会话的**实际库路径**被断言为 `/data/users/<handle>/ai-memory.db` 并写入审计 |
| AC4.4 | **负向**：人为把模板的 `AI_MEMORY_DB` 置空 → 门户**拒绝**启动会话并告警（**不得**静默落 `/data/ai-memory.db`） |
| AC4.5 | 会话开始前后，`/data/users/` 下**不出现**其他用户的库或临时文件 |
| AC4.6 | 会话**不跨用户复用**（禁会话池）——一会话一子进程 |

## S5 审计可追溯

> 作为**管理员**，我希望审计视图覆盖关键事件，以便事后对账「这次会话落在哪个库」。

| AC | 描述 |
|---|---|
| AC5.1 | 覆盖事件：建用户 / 签发 / 轮换 / 吊销 / **每次会话开始** |
| AC5.2 | 会话审计行**含解析出的库路径**（事后可判断隔离是否被正确钉住） |
| AC5.3 | 审计与日志中**不出现**令牌明文、不记录 MCP 报文正文（只记 `key_prefix`） |

## S6 接入说明页与 i18n

> 作为**新用户**，我希望有一个说明页告诉我怎么接入，以便 ≤ 3 步完成配置。

| AC | 描述 |
|---|---|
| AC6.1 | Home（接入步骤：获取 key → 配置客户端 → 验证）+ Admin 入口 |
| AC6.2 | 新用户按页面指引可在 ≤ 3 步内完成接入并成功调用一次工具 |
| AC6.3 | i18n **限定**门户 UI 与接入说明页（MCP 服务本身不做 i18n）；至少中 / 英双语，新增语言不改业务逻辑 |

## S7 容量、配额与限流

> 作为**管理员**，我希望用户不会写爆盘或拖垮服务，以便服务稳定。

| AC | 描述 |
|---|---|
| AC7.1 | **复用上游**：`[limits].max_memories_per_day` / `max_storage_bytes` / `max_links_per_day`（均 per-(agent, namespace) ⇒ 一用户一库一 agent 天然等价 per-用户）、`max_page_size` —— 以配置实现并核验生效（改配置后超限写入**被拒**） |
| AC7.2 | **实测给出结论**：`[limits].max_inflight_requests` 是 HTTP 准入控制，**对 stdio MCP 很可能不生效**，需实测后登记 |
| AC7.3 | **门户自建**（上游无「会话」概念）：每 key 并发上限、全局并发上限、空闲超时、单会话最长时长 —— 超限时**明确拒绝**而非排队致死 |
| AC7.4 | FS 级磁盘配额（覆盖 WAL 与临时文件）方案定稿 —— `max_storage_bytes` 只是库内计数 |

## S8 主人保底路径不受影响

> 作为**主人**，我希望门户挂掉时仍能读写自己的记忆。

| AC | 描述 |
|---|---|
| AC8.1 | SSH stdio 路径（`ssh ai-memory`）**保留**且在门户故障时可用 |
| AC8.2 | 门户用户目录与 SSH 路径**指向同一批文件**（`/data/users/<handle>/`）⇒ 同一用户两条路径互通，不出现两座孤岛 |
| AC8.3 | 门户容器**不挂载** docker socket（β′ 机制，验证项见 [`web-test.md`](./web-test.md)） |

## S9 门户自身数据的边界

> 作为**运维**，我希望门户自己的库不与用户记忆混放，以免备份脚本误收。

| AC | 描述 |
|---|---|
| AC9.1 | 门户库位于**独立卷**（如 `admin_portal_data` → `/srv/portal`），**不在** `/data` 下 |
| AC9.2 | 备份脚本遍历 `/data/users/*/ai-memory.db` 时**不含**门户库；门户库**单独**纳入备份与外迁 |

## 范围外（明确不做）

自助注册 · 对外收费/计费 · 非 MCP 接入面（REST / Web SDK / OpenAI 兼容）· 上游能力之外的二次开发 · 服务器 OS 账号同步（单账号 + N 密钥已足够）· 用 macaroon 能力令牌做隔离（additive-only，只放宽不收紧）。
