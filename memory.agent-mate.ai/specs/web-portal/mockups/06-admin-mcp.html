How you sign in

Your identity is the email or Google account listed in the Cloudflare Access policy. There is no password in this portal, so there is nothing to reset.

Ways in
Google account — primary
Email one-time code — backup

Keep more than one key

List at least two emails in the policy. Any one of them gets you in, so losing a mailbox is not a lockout.

  • Two or more emails listed in the policy
  • A Google account set as the primary login
  • Cloudflare recovery codes stored offline

Session

A session lasts about a month today. Three months is the target; the platform may cap it lower. A new device asks you to verify again.

Where
Cloudflare Zero Trust → Access → Applications → your admin host.
Session
Set session duration there. The console caps it at 1 month; longer needs the API. Applies to new logins.
Sign-in
Google is primary, email one-time code is the backup. A new device asks again.
Who gets in
The emails in the Allow policy. Add a second one so a lost mailbox is not a lockout.

If you lose access

Sign in to Cloudflare to change the policy, or use the SSH path, which never goes through this portal.

Open Cloudflare Access

Admins are added and removed in Cloudflare Zero Trust. This page only shows how it works.

Add an admin
In Zero Trust, open Access → Applications → your admin host → Policies → Allow, add the email, save. They sign in with that email — there is nothing for you to send.
Remove an admin
Delete the email from that Allow policy. Access ends on their next request; there is no session to revoke.
No password
There is no portal password to set or reset. A new device verifies again.
