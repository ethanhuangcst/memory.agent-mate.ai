## Learnings

### A · 2026-09-21～23，用户提出并定稿，Sprint 4 早期回顾（stories / Replan / 体例 / 门禁）

<a id="l1"></a>
**L1 · 编号空间会撞名；编号基准与锚点 id 都是易失坐标。** 故事号 `S1`–`S13` 与既有的「静默失败点 `S1`–`S4`」、`i18n-probe.sh` 的测试标签 `S1`–`S12` 同形，`grep` 清扫会同时命中三者 ⇒ 既可能误改、也可能因噪声漏判（5 个条目的错指正是这样被掩盖的）；重排时「原 Sprint N」在三种编号基准下含义不同，不写「编号基准」必然自相矛盾；条目跨 Sprint 迁移后锚点 id 仍叫 `s4-*`，不声明「id 前缀 ≠ 当前序号」后来者会按前缀反推并改错。落点：[`../docs/spec-doc-conventions.md`](../docs/spec-doc-conventions.md) 第 10 条。

<a id="l2"></a>
**L2 · 「双向可查」不会自动成立。** 索引里声明落点，被指的那一行**不会自己长出回链** ⇒ 声明双向等于承诺**同批回填**（同 L1 文档第 11 条）。

<a id="l3"></a>
**L3 · 同一事实两处写法会立刻分叉**（`S12` 的用例集合在故事索引与「已知限制」表各写一遍，第一次就漏了 `TC-P-L1-09`）。**复现于** O 轮（能力表被误加进「不得溢出」清单）。

<a id="l4"></a>
**L4 · 体例一旦写下，实例立刻受它约束 ⇒ 判据 / 体例落地后必须拿既有实例回代。** 新写的 `§2.4` 判据点名禁用「联调」这类动作词，而同批给 Sprint 5 起的批次名恰好叫「本地联调」；「有角色」与「交付给开发者自测」互斥。**复现于** N 轮（分类判据要逐条回代：`portal-acceptance` 按判据该归「入口 + 回归」而非探针）。

<a id="l5"></a>
**L5 · 重排 / 改名的同步面必须区分「历史叙述」与「活跃引用」，并要回头重扫「我已改过」类声明。** 一次批次拆分牵动故事索引（14 行落点）、`product-backlog` 关联列、`web-test.md` 的 D1 落点、`issues-log.md` 批次标题与**四个被外部引用的锚点**；「历史叙述」（ADR、`change-log` 流水、回顾正文）**不改**，「活跃引用」（计划 / 索引 / 台账）**必改**。另有一类**没有任何自动护栏能发现**的矛盾：`deployment.md` 变更记录写着「三处 Sprint 由 5 改为 6」，而 2026-09-23 重排把生产上线放回 Sprint 5 ⇒ **正文对、声明错**。

<a id="l6"></a>
**L6 · 「零残留 / 已扫齐」类声明必须写明扫描面并真扫到。** 文档扫干净后，`limits-probe.sh` 的输出串与 `maintain-user-dbs.sh` 的注释仍在引用旧编号 ⇒ 验证声明若不含脚本与制品，就是**自证不实**。

<a id="l7"></a>
**L7 · 用行号范围读文档前，先确认「这几行属于哪张表」。** 同一文件里有 7 张同构 Sprint 表 ⇒ 行号是**易失坐标**；据此把 Sprint 5 的行当成 Sprint 6，误报「Sprint 号写错」并差点改坏本来正确的内容。

<a id="l8"></a>
**L8 · 门禁自己也会坏，而且坏了与「没问题」同形。** 官方 E2E 入口 `portal-e2e.sh` 长期**起不来**（缺 `PORTAL_TEST_JWT_EMAIL`）且**会静默把测试跑在别人的实例上**（无端口预检）⇒ 唯一能自动发现布局类问题的入口等于不存在 —— 这才是 Issue 8 一类缺陷只能靠肉眼发现的**机制性原因**。**复现于** K 轮（四个真上游脚本 `rc` 恒为 `0`，门禁在 CI 里永不红）· M 轮（验收门禁自身的偶发）· P 轮（判据假红）。

### B · 2026-09-22，Agent，UI 迭代轮

<a id="l9"></a>
**L9 · 「类名在原型里用了、CSS 里没有规则」是本轮最多缺陷的共同形态**（`.dialog-actions` / `.dialog-target` / `.btn-danger` / `.section` / `select` 五处）⇒ 造组件后必须回扫「类名 ↔ 规则」对账，并登记「缺失规则时的表现」（[`adr/ADR-018`](../../adr/ADR-018-mockup-as-clickable-simulation.md) 第 5 条）。

<a id="l10"></a>
**L10 · 布局类断言与度量单位各有陷阱**：`is_visible()` 对**溢出容器内**的元素仍算「可见」⇒ 必须断言 `scrollWidth <= clientWidth` **且**元素右缘在视口内；网格项上的 `margin-inline: auto` 会取消 stretch（`.content` 在 390px 视口下变 696px）；`rem` 基准是 **17px 而非 16px**，按 16 估会系统性偏小。

### C · 2026-09-22，Agent，PSP-W1 实现轮

<a id="l11"></a>
**L11 · 同一件事在文档与实现里各写一次，就一定会分叉** —— 收口办法不是「下次注意」，而是**加可机械核对的护栏**（词表键存在性 · 四语言键集合一致 · `:root` 变量数 == 文档总表 · 中文变体不出现「令牌/權杖」）。

<a id="l12"></a>
**L12 · 缺键 / 缺配置必须 fail-loud。** 静默回落会把「键名打错」伪装成「文案待补」（`nav.mcp` 就这样躲过类型检查，最后靠视觉自检才发现）。

<a id="l13"></a>
**L13 · E2E 的环境是隐式输入。** 无头浏览器不发 `Accept-Language` ⇒ 门户回落默认语言 ⇒ 英文断言全挂（页面本身没错）；跨步骤写入的 cookie 也会污染后续断言 ⇒ E2E 必须**显式固定语言与状态**。

### D · 2026-09-23，用户提出并定稿，SBI 颗粒度复盘

<a id="l14"></a>
**L14 · 批次的实际装载量与它写下的交付判据会严重脱节。** `PSP-W1` 的判据是一行五步闭环，但同一批实际装了**至少 9 个本可独立交付的增量**（两条本机测试路径 · 隧道与真身份 · 开发登录入口 · 401 自诊断 · 覆盖率门禁 · UI 迭代三轮 · 身份收口 · 弹窗版式与布局护栏），**判据一行没改**；失控的痕迹就在回顾里 —— 每出现一次「**同日补充**」就是一批在收口期又吸收了新工作。代价最终落在最基础的增量上：「人能不能登录」排在最后，而当时的「已验」建立在 curl 与 Playwright 上，**两者都绕过了人手**。用户定稿：颗粒度太大 ⇒ 拆 SBI（[`adr/ADR-016`](../../adr/ADR-016-sbi-delivery-granularity.md)）。

### E · 2026-09-23，用户提出并定稿，UI 质量复盘

<a id="l15"></a>
**L15 · 「可看」不等于「可走」。** `#5` 的 134 项断言全是**渲染结果**，不含「点第二次 / 提交后落点 / 错误落在哪里 / 刷新后状态」⇒ 交互类缺陷（相对链接点第二次 404 · 重名报错被遮罩盖住 · 长值撑出边框）只能等真实实现才暴露；UI 在交付后被动三轮，本身就是「**没有增量确认**」的代价。用户定稿：UI 也是增量式确认，把 mockup 变成**可点击的全路径仿真**（[`adr/ADR-018`](../../adr/ADR-018-mockup-as-clickable-simulation.md)）。

### F · 2026-09-23，用户提出并定稿，缺陷逃逸复盘

<a id="l16"></a>
**L16 · 逃逸的都是低级缺陷，共同根因是「那条约束没人写」** —— 重名建用户看不到报错（错误渲染在弹窗**外**）· 「停用用户还能签发」被判为缺陷（`D13` 只写了「停用可逆」）· 长值撑出边框 · 弹窗点第二次到 API 地址，分别对应「冲突 / 重复如何处理」「错误提示出现在哪里」「状态前置条件」「二次操作落点」**四类都没在 spec 里写明**。用户定稿：至少在设计 spec 里写明白 common sense 能写出的基本设计约束（[`adr/ADR-019`](../../adr/ADR-019-spec-basic-constraints-and-executable-uptake.md)）。

<a id="l17"></a>
**L17 · 覆盖率绿灯 ≠ 覆盖到缺陷面。** 门禁当时已达标（语句 92.78 / 分支 85.90），但布局、交互、二次操作**不在 vitest 覆盖范围内** ⇒ 只有端到端才会暴露。

### G · 2026-09-23，用户提出并定稿，Replan 复盘

<a id="l18"></a>
**L18 · 「一个 Sprint 一个闭环」与「Sprint 内颗粒度」是两个正交判据，只看一个必然切错。** 把「上线」整体压进 Sprint 4 消除了跨 Sprint 依赖，却让该 Sprint **首次引入 3 项新技术**，违反 `ADR-016` 的「一个 SBI 最多首次引入一项技术」。

<a id="l19"></a>
**L19 · 依赖链的长度由「同一件事被切成几段」决定**，不是由「上线排在第几个 Sprint」决定 —— 关键一步是问「**为什么桥在 Sprint 4、合跑在 Sprint 5**」（同一件事被切成两段才是 4 跳链的成因）。

<a id="l20"></a>
**L20 · 同一件事的「判据面」与「实测面」会分置两个 Sprint 而无人察觉**（`deploy:用户规模上限` 与 `用户规模上限定值` 直到并排对比才发现是同一件事）。

<a id="l21"></a>
**L21 · 门禁会在新写的记录里反过来抓错**：新写的变更记录里带了一处通配符链接（`adr/ADR-008-*.md`），被 `make doc-links` 当场拦下 ⇒「变更记录」本身也是被门禁覆盖的对象。

### H · 2026-09-23，Agent，3.1 实现轮

<a id="l22"></a>
**L22 · 协议事实优先于直觉，且要实测两次才敢下结论。** 上游无响应时在 HTTP 层加超时是「退出码对、行为错」—— Streamable HTTP 的响应是 **SSE 流、响应头先于上游结果发出** ⇒ 「上游太慢」**根本无法用 `504` 表达**，规格里那一行是被实现推翻后重新定档的。

<a id="l23"></a>
**L23 · 判据 / 验证器自己会骗你（假绿型谱）。** 三个实例：断言「子进程已回收」用 `ps`（容器**没有 `ps`** ⇒ 恒真假绿）· 用 `/proc/<pid>/exe` 判二进制又踩 **Rosetta**（所有 exe 都指向转译器 ⇒ 恒零）· 判「取消通知已转发」用「上游是否落文件」得**假阴性**（`cancelled` 在每一跳都被 SDK 内置消费），改判 stdin 留痕才成立。**复现于** K / L / M / P 轮（门禁退出码恒 0 · 覆盖了≠证到了 · 偶发 · 判据取行方式）。

<a id="l24"></a>
**L24 · 类型定义可以是谎话，而它撒谎的方式是「静默」。** `ProtocolOptions` 声明了 `fallbackRequestHandler` / `fallbackNotificationHandler`，但运行时构造函数只把 options 存进 `_options`、从不提升为实例属性 ⇒ 按类型提示写会**静默失效**（请求侧被合成 `Method not found`、**通知侧连错误都没有**）。

<a id="l25"></a>
**L25 · 故障注入撞墙时，缺的往往不是手段而是「接缝」。** 外部手段（发非 `initialize` 请求 / 无 `method` 的响应）**全被 SDK 优雅处理掉**；真正解决的是**可注入的模块边界**（`createBridgeTransport` 独立模块 ⇒ 可用 `vi.mock` 换成「按指令抛错」的假传输），两条分支因此被**确定地**覆盖。

<a id="l26"></a>
**L26 · 借壳开发开关的语义边界必须在 spec 里写死。** `PORTAL_LAUNCH_OVERRIDE` 只覆盖 `command` / `args`，**env 由覆盖命令自己负责转发** —— 漏了这句的后果不是报错，而是「`memory_store` 成功但数据落到共享主库、身份退回上游默认值」。

<a id="l27"></a>
**L27 · `Done` 的判据若只覆盖「跑通」，就会把「契约完整」漏给下一轮。** `3.1` 交付后的 code review 找出四处缺口（桥只注册 4 个方法 ⇒ 其余由桥自行合成 `MethodNotFound`；能力与版本硬编码），本地**完全看不出来**，但会在「换 profile / 上游升级 / 上线排障」时立刻变成问题 ⇒ `3.1` 自 `Done` 退回 `WIP`。行动：接入 / 协议类批次把 **code review 写进批次内的收尾步骤**，且「桥自称原样转发」这类**自我声明**要有断言去证伪。

<a id="l28"></a>
**L28 · 脚本层三个坑**：macOS 的 bash 3.2 在「`$var` 紧跟全角字符」时会把全角并进变量名（须写 `${var}`）· `[ ... ] && return` 会把 `$?` 污染成 1（**全部断言通过、退出码却恒为 1**）· 未加引号的 heredoc 里**注释的反引号会被当命令执行**。**复现于** J 轮（同一天栽两次）· M 轮（不要编辑正在运行的脚本）。

### I · 2026-09-24，Agent，3.2 / 3.9 实现轮

<a id="l29"></a>
**L29 · 判据要按语义判、不能按字面判（五个实例，同源）。** ① `3.1` 的「超时口径」(`504` 不适用于任何上游超时) ② `3.9` 的「逐字节透传」（schema 会**重建键序**，`JSON.stringify` 比 `serverInfo` 假失败）③ `3.2` 的「路径断言」（`alice/../bob` 的字面路径**能通过全部三项断言**，归一化后才指向**他人**库）④ `3.3` 的「用户目录之外零变化」（上游会更新**共享**审计日志）⑤ `3.4` 的「僵尸进程」（僵尸的 `/proc/<pid>/cmdline` **是空的**，只能读 `stat` 的 `state` 并按 `comm` 认名）。

<a id="l30"></a>
**L30 · 说「某分支不可达」时必须同时说清「对什么而言」不可达。** 「不变量 1 的 spawn 侧复述不做，因为不可达、只会稀释覆盖率」这条论据**部分不成立**：「不可达」只对**生产 / 集成路径**成立，对**覆盖率**不成立（判定抽成导出纯函数后单测直接可覆盖）。

<a id="l31"></a>
**L31 · 加一层校验会改写既有分支的原因归属。** 复用 `validateHandle` 后 `alice/../bob` 先在 handle 关被拦、归 `invalid_handle` —— 不是缺陷（根因更精确），但**文档、单测、端到端断言三处都得跟着改**（一次「加一行」触发 2 处 spec + 2 处测试的连锁修正）。

<a id="l32"></a>
**L32 · 否定命题需要专门的判据。** 「上游**未被** spawn」不能靠 `--env-dump`（无法区分「没起」与「起了但在 dump 前退出」）⇒ 新增标记脚本把「被执行」变成**第一个动作**，「标记文件不存在」才成为强判据。先问：**我这个观测点，在出问题时会不也给出同样的静默结果？**

<a id="l33"></a>
**L33 · 能力断言发生在「注册期」⇒ 装配顺序是硬约束。** 「能力取自上游」+「无条件注册业务 handler」= **上游缺该能力时网关在构造期抛错** —— 按直觉直接实现的话，缺陷**只在特定上游档位暴露**（本地永远看不到）；代价对比：探针半天 vs 上线后一桩「某些用户连不上」的悬案。

### J · 2026-09-24，Agent，3.3 / 3.4 实现轮

<a id="l34"></a>
