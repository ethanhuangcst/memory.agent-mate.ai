# ADR-014: 门户管理面身份只信签名断言，本地开发经隧道取真身份

## Status
Accepted

## Context

`PSP-W1` 要实现管理面（建用户、签发/轮换/吊销令牌）。设计文档 `web-portal/web-design.md` §6 / §6.1 定了「管理面身份由 **Cloudflare Access** 认定、门户**不建账号、不存密码**」，S10 的验收条件又要求「未认证无法访问管理面（`AC10.1`）」「已认证管理员正常使用（`AC10.5`）」。

但落地时暴露一个**全仓此前没有规定**的问题：**本地开发如何替代 Cloudflare Access？** 同时自动化测试还遇到第二个问题：**浏览器 SSO（Google 登录）无法被 Playwright 自动化**，必须选一条机器访问路径。

候选方案与当时的顾虑：

| 方案 | 顾虑 |
|---|---|
| 本地加「dev 绕过头」（`PORTAL_DEV_AUTH`） | 多一条**与生产不同的认证分支**，正是「本地能过、线上失效」的温床；且必须再加一道「生产禁止启用」的防护才安全 |
| 本地跑 oauth2-proxy / 自建登录页 | 引入第二个认证组件（多一层无用组件、多一套配置） |
| 本地用**命名隧道**把回环端口暴露到受 Access 应用保护的主机名 | 需要 Cloudflare 账号、域名与网络；离线不可验收 |
| 只验面隔离（`Host`），认证整条留给生产 | `AC10.1`/`AC10.5` 在本地**完全不可验**，等于把风险推迟 |

## Decision

1. **身份来源只有一处：Cloudflare Access 的签名断言。**
   - 取断言：优先 `Cf-Access-Jwt-Assertion` 头，**浏览器导航回落到 `CF_Authorization` cookie**（生产本来如此）；
   - 验签：JWKS + `iss` + `aud` + `exp`（含 30s 时钟偏移）；
   - `CF-Access-Authenticated-User-Email` **只作交叉校验**：与断言内 `email` 不一致即判 401，**绝不单独采信**（该头可伪造）。
2. **Access Service Token 不需要专门代码**：它由 Cloudflare 在边缘校验后注入**同一断言**（此时断言只有 `common_name`）。门户据 `common_name` 把来源记为 `service-token`，仅用于审计与排障。
3. **本地开发用命名隧道 + Access 应用**取得**真身份**，不引入「本地关掉认证」的分支。
4. **自动化测试分两层**：
   - **离线**：自签 JWT（测试密钥对）覆盖验签与状态机分支，**零网络**、可重复执行；
   - **在线**：Access **Service Token** 头验证真链路；缺前置时以**明确退出码跳过**（`make portal-e2e ARGS=--online` 返回 40），**不伪装通过**。
5. **fail-closed 姿态**：`PORTAL_ENV=production` 下必须配齐团队域与 `aud`，且**启用自签通道即拒绝启动**；若 Host 非回环而自签通道开启，同样拒绝启动。

## Rationale

- 选「隧道取真身份」而不是「dev 绕过头」，是因为**认证是最不该有两条分支的地方**：本地跑的是同一段验签代码、同一套失败语义，`AC10.1`/`AC10.5` 才能在本地真的被验。
- 选「签名断言 + 交叉校验头」而不是「信任注入头」，是因为注入头由请求方携带，**在未经过 Access 的路径上可伪造**；只有签名断言能证明身份来自 Cloudflare。
- 选「双层测试凭据」是为了同时满足两个相互拉扯的要求：**保真**（真 Access 链路必须被测）与**可复跑**（离线必须能跑）。把两者分开，各自取到自己的最强项；代价是必须**如实登记「离线不覆盖真 Access 链路」**，而这正好由退出码 40 的跳过语义强制显式化。
- Service Token 走「零专门代码」是因为 Cloudflare 已在边缘完成校验：门户再验一遍 client id/secret 会变成**第二份凭据副本**与第二处失效点。

## Consequences

- **正面**：认证代码只有一条路径；本地与生产同源；`AC10.1`/`AC10.5` 可本地验（离线验逻辑、在线验链路）；`PSP-W2` 的 `/mcp` 可以直接消费同一个令牌校验函数。
- **代价**：本地端到端验收依赖 Cloudflare 账号与网络（本机当时**未装 `cloudflared`** ⇒ 在线套件以 40 跳过，此项**未在本地完成**）；离线套件的密钥是测试密钥对，**不得**与任何真实密钥混用（配置层已限制为回环 Host）。
- **后续**：`PSP-W2` 复用 `verifyToken` 时，必须让**对客户端的应答与失败原因解耦**（统一 401），否则原因会变成账号/令牌的枚举探针；`PSP-W3` 部署时把隧道路径换成生产反代（`§11` 步骤 2/3），本 ADR 的验签逻辑不变。
